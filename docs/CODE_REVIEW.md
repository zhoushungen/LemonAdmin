# Lemon v1.4 代码审核与精简记录

## 审核目标

在不削弱通用能力和安全边界的前提下，减少项目层级、依赖、重复状态、无调用代码和隐式行为。

## 已直接修复的高风险问题

1. **异常角色可能被解析为全部数据**  
   原查询通过 `COALESCE` 将缺失角色的数据范围兜底为 `All`。已改为默认 `Self`，并在登录、刷新 Token 和数据范围解析时验证角色存在且启用；异常即拒绝访问。

2. **缺失或禁用主部门仍可能进入系统**  
   普通管理员现在必须具有启用主部门。登录、刷新、数据范围解析和账号切换入口均 fail-closed。

3. **账号切换目标状态校验不完整**  
   启动账号切换前新增目标角色与主部门校验，避免进入无法正确授权的半登录状态。

4. **未知对象存储配置静默回退本地**  
   Provider 改为显式分支；配置错误直接启动失败，避免生产文件落到容器本地磁盘。

5. **客户端可注入任意 Correlation ID**  
   增加 64 字符上限和字符白名单，非法值改用服务端 TraceIdentifier。

6. **菜单可能形成父子循环或悬空父节点**  
   新增父节点存在、自身父节点和后代循环校验；删除前验证菜单存在。

7. **损坏的密码 Hash/Salt 可能触发 500**  
   Base64 格式异常现在按密码校验失败处理，不泄漏内部异常。

8. **前端损坏的 localStorage 可能导致页面启动失败**  
   登录状态、主题、字号和表格偏好统一使用安全 JSON 读取与值域校验。

9. **Refresh Token 并发重放可能生成多组新令牌**  
   轮换更新增加未撤销和未过期条件，并检查影响行数；同一个旧令牌只有一个并发请求可以成功。

10. **已有 Access Token 在角色或部门禁用后仍可能访问部分接口**  
    权限服务每次授权先验证账号、角色和主部门状态；当前菜单入口也通过数据范围服务验证，异常账号立即拒绝。

11. **登录页硬编码开发账号和密码**  
    已移除预填账号、预填密码和页面明文提示；开发凭据仅保留在 README 与开发 Compose 配置中。

## 已完成的结构精简

1. 删除 `Lemon.Shared`，后端由 5 项目精简为 4 项目。
2. 删除 Mapster；当前少量 DTO 使用显式构造和专用映射方法。
3. 删除 JWT 中重复的权限 Claims；后端授权只读取权限服务，前端权限随登录响应返回。
4. 删除重复的 `AddAuthorization` 注册并整理 NuGet 包所属项目。
5. 合并仅含单个 Requirement 的授权文件，减少样板文件。
6. 删除未调用的 `IRoleRepository.GetByCodeAsync` 和 `IAdminService.GetOptionsAsync`。
7. 格式化压缩成单行的 Controller，提升维护性，不增加运行复杂度。
8. Redis 默认前缀改为环境无关值，开发环境单独覆盖。

## 保留而未过度精简的部分

- 保留 Domain 项目：实体和核心身份规则仍值得独立。
- 保留 Repository 接口：Application 不应直接依赖 Dapper。
- 保留 FluentValidation：请求规则集中、可测试，收益高于依赖成本。
- 保留 Quartz：当前任务少，但作为通用框架需要稳定调度入口。
- 保留 Refresh Token：后台长期会话和强制下线需要它。
- 保留显式数据权限 SQL：不引入全局拦截器，避免隐式越权。

## 尚未自动修改的事项

1. `/health/ready` 当前只表示进程可响应，没有主动探测 MySQL、Redis 和对象存储。生产部署需要严格就绪探针时再增加，避免当前框架引入额外探测复杂度。
2. 文件上传按服务端扩展名白名单控制，尚未检查文件魔数或做病毒扫描。面向高风险公网上传业务时应扩展 `IFileValidator`。
3. Element Plus 主包有构建体积提示，但目前页面数量较少，不提前做复杂拆包。

## 验证要求

- `bash scripts/validate-package.sh`
- `npm ci && npm run build`
- `npm audit --omit=dev`
- 开发机安装 .NET 8 SDK 后执行 `dotnet restore` 和 `dotnet build -c Release`
